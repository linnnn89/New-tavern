# TavernDesk 独立跑团规则与实现

状态日期：2026-08-11（北京时间）

本文是跑团功能的单一规则文档，已吸收旧版产品设计、R1/R2 阶段说明和交接摘要中的有效内容。具体预算、记忆开关和长局验证方法见 [`TavernDesk-R2-B-Campaign-Context-Budget.md`](TavernDesk-R2-B-Campaign-Context-Budget.md)。

## 1. 产品结论

跑团是独立产品入口和独立数据域，不是普通群聊附加一段 GM 提示词。

当前闭环为：

```text
选择剧本与阵容
→ 冻结角色、规则、权限和模型路由
→ GM 建立场景
→ USER / AI 玩家提交行动
→ GM 裁定并更新世界状态
→ 低频更新跑团记忆
→ 进入下一轮
```

稳定边界：

- `1 名 GM + USER + 0–4 名 AI 玩家`；GM 可由 AI 或 USER 担任。
- 支持 USER 同时担任玩家与 GM，也支持纯观察模式。
- 普通聊天、普通记忆和跑团数据隔离；跑团过程默认不回写角色卡或普通记忆。
- 玩家只提交自己的行动意图；GM 是唯一能确认结果和推进世界事实的角色。
- 模型调用由用户明确触发，不自动无限续写、不自动重试、不静默跳过失败席位。
- 每次生成有独立 operation、缓存和终态；失败内容不进入 GM 裁定或后续记忆。
- 不建设通用多 Agent 框架、规则 DSL、地图、背包、属性系统或 NPC 独立模型席位。

## 2. 参与者与权限

| 身份 | 可以做什么 | 不能做什么 |
| --- | --- | --- |
| GM | 描述场景、NPC、环境，裁定行动结果，更新世界状态和下一轮提示 | 替玩家新增台词、心理、决定、反应或下一步行动 |
| USER 玩家 | 提交自己的行动与对白；使用 Persona 或局内设定 | 直接宣布未裁定结果、读取其他席位私密信息 |
| AI 玩家 | 按冻结角色快照提交自己的行动与对白 | 取得 GM/NPC/旁白权限，替 USER 或其他席位行动 |
| 观察者 | 查看公共事件，并可预约从下一完整回合加入 | 在冻结的当前回合中途改变参与者集合 |
| NPC | 由 GM 统一控制 | 在当前版本中占用独立模型席位 |

角色卡定义人物性格、背景、知识、能力和表达风格，不是权限来源。卡内指令不能覆盖当前席位身份，也不能让 AI 玩家取得 GM、NPC、旁白或故事作者权限。

USER 担任 GM 时不发起 GM 模型请求。若同时担任玩家，玩家行动与 GM 裁定是两个独立提交：先锁定玩家行动，再开放 GM 裁定区。

## 3. 数据与可见性

跑团使用四层信息：

| 层 | 内容 | 可见范围 | 是否回写普通聊天 |
| --- | --- | --- | --- |
| 角色源快照 | 角色卡、Persona、可选初始记忆 | 对应玩家与 GM | 否 |
| 公共事件 | GM 叙事、公开行动、对白与裁定 | 全体 | 否 |
| 私有事件 | 单席秘密、私聊、私有投递 | 对应玩家与 GM | 否 |
| GM 状态 | 未公开事实、时间线、场景状态 | GM；用户可主动查看导演视角 | 否 |

### 快照规则

- 开局复制角色核心字段、Persona 和用户明确选择的普通记忆；默认不导入普通记忆或原世界知识。
- 角色卡、剧本世界规则、GM 指令、叙事权限和模型路由在开始时冻结。
- 开局后修改源角色、普通记忆或剧本，只影响以后新建的局。
- 跑团记忆属于某一局。若未来要带回普通记忆，只能生成用户可编辑并明确确认的合并草稿。

### 持久化对象

| 对象 | 职责 |
| --- | --- |
| `campaign_scenarios` | 可复用剧本、世界设定、公开规则、GM 开场与导入原始数据 |
| `campaigns` | 单局状态、流程、轮次、冻结设置、预算、模型路由与场景状态 |
| `campaign_participants` | USER/AI 席位、角色/Persona/记忆快照和单席模型覆盖 |
| `campaign_events` | 唯一权威事件流：行动、裁定、私有投递、状态变化、失败与重试 |
| `campaign_memory_banks` | GM/Public 长期记忆投影 |
| `campaign_memory_checkpoints` | 各记忆范围已处理到的事件序号与轮次 |

`CampaignEvent` 是权威事实源；记忆和场景状态是可重建的派生结果。只有已完成、已锁定且通过校验的事件可以进入后续上下文和记忆。

## 4. 状态与三种流程

### 跑团状态

```text
Draft → Opening → AwaitingActions → Resolving
                         ↑              ↓
                         └──────────────┘
```

活动状态可暂停，完成后可归档。当前不持久化跨进程存活的并发 barrier；异常退出时遗留的 `Queued/Streaming` 尝试收尾为可显式重试的 `Interrupted(ProcessExited)`。

### 生成状态

```text
Queued → Streaming → Completed
   └──────────────→ Interrupted / Failed / ProtocolViolation
```

每个 operation 只允许一个终态。停止、Provider 错误、协议失败和正常完成竞争时，第一个终态胜出；之后到达的流片段不得改变事件、回合、记忆或场景状态。

### 流程预设

| 预设 | 行动方式 | 未裁定行动可见性 | GM 裁定 |
| --- | --- | --- | --- |
| 协作圆桌 | 稳定桌序，可触发尚未行动席位 | 提交后公开，但仍只是提议 | 全员锁定后批量裁定 |
| 秘密同投 | 同一冻结快照下有限并发 | 本轮仅提交者和 GM 可见 | 全员锁定后批量裁定并揭示 |
| 严格先攻 | 固定顺序逐席行动 | 默认公开，可有单次私密 | 每席行动后立即裁定 |

三个预设共享一条硬规则：未被 GM 裁定的玩家内容不是世界事实。

`CampaignFlowEngine` 按预设路由到独立策略。策略统一计算：

- 当前允许行动的席位；
- GM 本次允许裁定的 `PlayerIntent` 清单；
- 候选链与事件可见性；
- 裁定成功后的轮次和席位位置。

UI、Runner、Context Planner 和仓储提交都消费同一计划，不能各自扫描事件并重新猜测流程状态。

## 5. 一轮如何执行

### 玩家行动

1. 系统读取 Flow Engine 的当前行动者和冻结事件序号。
2. USER 主动提交，或用户明确触发对应 AI 席位生成。
3. AI 输出先留在该席位的独立尝试中；非完整结果不进入裁定。
4. 完整 USER/AI 行动与系统生成的 `1d20` 在同一原子写入中锁定。
5. 骰点沿用行动可见性，并同时保存显性正文和结构化数据。

`1d20` 表示情境倾向，不是固定成功表。GM 仍需结合角色能力、方法、风险和既有事实裁定；纯对白或低风险行为不能因为低点数被抹除。额外的 `NdM±K` 只创建独立公开骰点记录，不替代行动自动骰。

### AI 玩家上下文

AI 玩家请求按事件生命周期分为：

1. 已裁定共同历史；
2. 最新 GM 场景与裁定；
3. 当前流程允许看见的本轮其他席位提交；
4. 当前席位任务。

每条运行时 JSONL 都带稳定的 speaker 身份和 resolution status。平级玩家可以感知或回应公开表达，但不能把别人的行动成败、观察结论或世界影响写成已确认事实。

严禁加入：其他席位私有记忆、未授权的本轮意图、GM-only 状态或普通聊天的实时记忆引用。

### GM 裁定

1. Flow Engine 给出本次唯一的待裁定 `PlayerIntent` 清单。
2. Planner 组装已裁定历史、最新场景、冻结资料、本轮行动、骰点、GM 记忆和输出协议。
3. 叙事权限编译器按流程和剧本冻结设置生成本次权限契约。
4. AI GM 生成正文与隐藏的结构化变化声明。
5. Validator 校验已解决席位、变化类型和来源行动。
6. 通过后剥离隐藏声明，原子保存可见正文、场景状态和回合推进；失败候选留痕但不锁定。

AI GM 还必须提供非空的 `【下一轮评定参考】` 结尾。缺失、结构无效或叙事权限校验失败时，本次尝试保留为诊断候选，不更新世界事实、记忆或轮次，用户必须显式重试或切换模型。

### 叙事权限

剧本分别控制新增 NPC、角色关系变化和独立剧情线：

- 禁止；
- 仅限玩家本轮明确提交；
- GM 可自主裁定。

严格先攻只授权当前席位；协作圆桌和秘密同投只授权本次 resolution plan 中已经提交的席位。权限层不重新推导行动者或轮次。

当前门禁依赖强约束 Prompt、模型结构化自报和确定性校验。它不能保证识别模型正文中所有“未申报的语义越权”；只有真实样本证明必要时，才评估本地规则或独立校验模型。

## 6. 上下文、Token 与记忆

`CampaignContextPlanner` 同时生成实际 Provider 请求和 UI 预算明细。它按以下优先级处理：

```text
固定资料与安全规则
→ 最新 GM 场景和当前回合
→ GM/Public 长期记忆
→ 近期已裁定事件
→ 更旧历史
```

固定资料和当前回合属于 mandatory context，超限时明确阻止。长期记忆有独立上限；旧历史可以按预算退出，但不能挤掉当前场景或未裁定行动。详细参数与诊断语义见上下文与记忆指南。

跑团记忆采用两份独立投影：

- `GM Memory`：可包含 GM 可见的完整已锁定事实；
- `Public Memory`：只从公共事件生成，不能由 GM Memory 二次“脱敏”得到。

记忆更新只处理 checkpoint 之后、截至最近成功 GM 裁定的已锁定事件。失败不推进 checkpoint，也不回滚已保存的裁定。每局关闭记忆后不调用总结模型、不注入长期记忆，但保留已有 bank/checkpoint 供以后继续。

当前没有 `CampaignFact`、Participant Memory 或向量化跑团事实层。若真实长局证明文本投影不足，应另行确认数据模型，不能把玩家意图直接写成已确认事实。

## 7. UI 工作流

### 剧本库与准备大厅

准备大厅完成三组设置：

1. 世界与 GM：剧本、规则、主持方式和 GM 模型；
2. 队伍：USER 参与方式、0–4 个 AI 席位、角色/Persona/可选记忆快照；
3. 流程与模型：流程预设、默认模型、多模型阵容、上下文和输出设置。

开始前应能看见最终有效 Provider/模型与将发送的内容类别，但不得读取或显示 API Key。

### 游戏桌面

- 左侧席位区按稳定桌序显示身份、模型和单一当前状态。
- 中间事件流保存不可变历史、失败尝试、候选和重试入口。
- 右侧“当前步骤”只显示此刻允许的主操作，避免让用户从平级按钮猜流程。
- 额外掷骰、模型调整、记忆与上下文设置作为次要工具，不与主流程争夺焦点。
- AI GM 只在用户点击裁定后调用；失败后显示重试，不自动继续。
- 观察模式不显示无效的 USER 输入；加入请求只在下一完整回合生效。

导演视角可以主动查看 GM-only 和私有内容，默认折叠并提示可能剧透。

## 8. 失败、取消与重试

- 同一席位、同一轮不能重复提交生效行动。
- 重试创建新 operation 和 attempt，不覆盖失败记录；正常完成并锁定的玩家行动不作为“重抽”入口。
- 单席位失败或取消不能删除其他已锁定行动。
- 非 `Completed` 的正文只作为有限诊断，不进入 GM 请求、记忆或其他席位上下文。
- 页面切换、重载或关闭子窗口不取消后台请求；用户取消入口由应用级“停止全部 API”统一管理。
- 全局停止先阻止新登记，再取消活动 operation，最后等待本地收尾并重新开放入口。
- 输出健康守卫只检测保守的连续精确重复，不引入语义模型；命中后停止该 operation 并保留有限诊断。
- 私有查询必须同时匹配 campaign 和 recipient；普通聊天检索不索引跑团私有或 GM-only 内容。
- 场景状态版本不匹配时拒绝提交旧裁定。

## 9. 已实现、未验证与延后范围

### 已实现

- 独立剧本、战役、席位、事件流和 GM/Public 记忆。
- 三种流程策略、USER/AI GM、观察模式和下一回合加入。
- 多 Provider/多模型席位、局内显式换模型、Token 门禁和预算预览。
- 公共/私有/GM-only 可见性、冻结快照和秘密同投互盲。
- 独立失败缓存、候选、取消、显式重试、异常退出收尾和唯一终态。
- 自动行动 `1d20`、额外公开骰子和 GM 裁定协议。
- 叙事权限编译、结构化变化声明、确定性接纳门禁和场景状态更新。
- 每局记忆 ON/OFF、低频 GM/Public 记忆更新和 checkpoint。
- 普通聊天、普通记忆与跑团零自动回写。

### 尚未充分验证

- 10–20 轮真实长局中的历史裁剪、记忆事实稳定性和 Token 成本。
- 记忆 ON → OFF → ON 的真实 Provider 请求边界与 checkpoint 行为。
- 多模型短局中的席位失败、途中换模型、秘密同投和全局停止。
- 各真实 Provider 的并发限制、首字延迟、流中断、usage 和计费行为。
- 叙事 Validator 对真实模型输出的漏报模式。

### 明确延后

- `CampaignFact`、Participant Memory、关系图、任务图和向量化跑团检索；
- 可跨进程恢复的同轮 barrier、统一截止时间和自动跳过策略；
- 战役分支/回滚、世界包、地图、附件、语音、背包和属性系统；
- 跑团经历自动写回角色普通记忆；
- Provider 特例矩阵、后台队列或通用 Agent/工作流框架。

这些候选只有在真实使用产生具体证据并经用户确认后才进入实现范围。

## 10. 验收不变量

1. 源角色卡、普通记忆、剧本卡和其他跑团不会被当前跑团自动修改。
2. 未导入普通记忆时，AI 玩家请求不包含普通聊天记忆；导入后也只读取开局快照。
3. 某席位上下文不含其他席位私有事件、私有记忆或 GM-only 状态。
4. 秘密同投的所有 AI 使用同一冻结序号，且互相看不到本轮草稿。
5. 协作圆桌可读取公开提议，但明确这些内容尚未被 GM 裁定。
6. 严格先攻只有上一席位裁定成功后才开放下一席位。
7. GM 只裁定 Flow Engine 提供的行动清单；重试不会重复推进世界状态。
8. 失败、停止、断流、超限或协议无效的内容不会进入 GM 上下文或长期记忆。
9. mandatory context 超限时阻止生成；历史裁剪必须有明确诊断。
10. Public Memory 不含 Private 或 GmOnly 事件，且更新失败不推进 checkpoint。
11. 每条成功玩家行动和它的 `1d20` 同时写入，失败行动不产生自动行动骰。
12. GM 不替玩家补写新选择；叙事权限校验失败时不锁定、不推进、不更新场景状态。
13. 全局停止后迟到片段不会创建事件、推进回合或覆盖记忆。
14. 关闭跑团记忆后无总结请求、无长期记忆上下文分区，近期原始事件仍可使用。

下一步不是继续扩展框架，而是按上下文与记忆指南完成真实短局和长局验证，再根据具体失败样本决定最小修复。
