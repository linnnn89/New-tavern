## 0. 设计北极星（全局原则）

1. **安静的工具感**：TavernDesk 是长时间阅读/写作的桌面工具，视觉重心应落在“内容”（消息、角色卡、设定文本），框架 chrome 退后。参考：Linear、Raycast、Arc、Notion 的“低饱和中性色 + 单一强调色 + 大量留白”。
2. **单一强调色原则**：全局只允许 1 个品牌强调色 + 语义色（成功/警告/危险/信息），禁止各页自带颜色。
3. **8pt 网格 + 4pt 微调**：所有 Margin/Padding/间距只取 4/8/12/16/24/32/48。
4. **层级靠字重/字号/明度，而不是边框**：能用留白分组就不用分割线，能用底色分区就不用描边。
5. **工程约束**：所有视觉值必须是 Token（`DynamicResource`），页面 XAML 禁止写死颜色/圆角/间距字面量；新增样式集中在 `Themes/`，页面只引用。

## 1. 应用壳层（MainWindow / AppicaShell.xaml）

证据：`首页-浅色-100.png`。

| # | 现状问题 | 改进方案 | 理由 |
|---|---|---|---|
| 1.1 | 导航选中态 = 蓝色 2px 描边 + 浅蓝底 + 蓝字，三重强调，视觉过重，像“输入框被聚焦” | 去掉描边；选中态 = `NavSelectedBackground`（中性 6–8% 灰或强调色 8% 透明度）+ 左侧 3×16px 圆角指示条 + 字重 SemiBold；图标与文字同色 | 描边语义是“焦点/可编辑”，导航选中应是“位置”。键盘焦点另用 `FocusVisualStyle`，避免两种状态混淆 |
| 1.2 | 顶部标题栏左侧“仪表盘”与左侧导航选中项重复；右上“本地工作区”与侧栏底部卡片重复 | 标题栏只保留：页面级面包屑（如“角色 / 艾琳”）+ 全局搜索入口（Ctrl+K 预留位，可先不实现）+ 窗口按钮；“本地工作区”只在侧栏底部出现一次 | 信息只出现一次（单一事实来源），节省最贵的顶部横向空间 |
| 1.3 | 侧栏底部“停止全部”按钮常驻，即使“当前无生成请求” | 默认隐藏；有生成任务时以状态胶囊出现（“生成中 · 2”+ 停止图标按钮），使用警示色而非中性按钮 | 常驻的危险操作会被习惯性忽视（banner blindness），按需出现才有信号价值 |
| 1.4 | 品牌字标 `TavernDesk` 是大号粗体纯文本，占 120px 高度 | 字标缩至 18–20px SemiBold + 16px 应用图标，顶部区域高度与标题栏对齐（同一水平线），释放侧栏纵向空间 | 桌面工具的品牌位应克制；与标题栏对齐可形成统一的顶部基线 |
| 1.5 | 侧栏与内容区仅靠 1px 竖线分隔，侧栏白、内容灰，层级反了（chrome 比内容更亮） | 采用“内容最亮”原则：侧栏 `SurfaceSunken`（略灰），内容区卡片/画布 `SurfaceBase`（白或近白）；去掉竖分割线 | 人眼优先注意高亮区域，应把最亮的面积给内容 |
| 1.6 | 侧栏宽度固定约 245px，无折叠 | 增加窄栏模式（仅图标，56px），窗口宽 < 1280 时自动切换，并记忆用户选择 | 聊天页三栏在 1080 宽时非常挤（见第 3 节），侧栏是最可压缩的区域 |

工程落地：
- 新增 Token：`NavItemSelectedBackground`、`NavItemIndicatorBrush`、`SurfaceSunken`、`SurfaceBase`、`SurfaceRaised`（同步加入 `InterfaceSettingsRuntime` 四套主题字典与 `Light.xaml` 默认值，遵守 P4 文档“XAML 默认值必须存在”的约束）。
- 导航项改为一个 `NavItemStyle`（ListBoxItem/RadioButton 模板）集中定义，MainWindow 中删除逐项的局部 Setter。
- 1.6 需要 `MainWindow` 增加一个 `IsNavCompact` 视图状态，属于小范围行为改动，单独提交。

| 3.2.5 | 会话列表：角色分组头和其下会话重复显示同一标题与摘要；折叠符号 `^` 很小 | 分组头只显示角色头像+名称+会话数，摘要只在会话行显示；折叠用 chevron 图标（12px，旋转动画 150ms） | 去重；chevron 是通用折叠语义 |
| 3.2.6 | 会话选中态 = 左侧蓝色竖条 + 浅蓝底 + 蓝框，与导航选中态（1.1）规则不一致 | 与导航统一使用 `ListItemSelected` 规则（底色 + 指示条，无描边） | 同一应用中“选中”应只有一种视觉语言 |

### 3.3 消息与输入区

| # | 现状问题 | 改进方案 | 理由 |
|---|---|---|---|
| 3.3.1 | 消息操作栏（`…`、朗读、齿轮）常驻在每条消息下方 | 默认隐藏，hover/键盘焦点进入消息时淡入（Opacity 0→1，120ms）；最后一条 AI 消息常驻“重新生成/朗读” | 长对话中常驻操作栏会形成大量重复噪声 |
| 3.3.2 | 气泡为白底 + 灰描边，与画布对比弱；用户/AI 消息仅靠位置区分 | AI 消息：无气泡、全宽排版（阅读型，类似 Claude）；用户消息：右侧强调色 8% 底色气泡、无描边。“气泡模式”保留给偏好者，默认改为“文档模式” | 角色扮演以长文本为主，无气泡排版的阅读效率更高；默认值变更需用户确认（见 §9 待决） |
| 3.3.3 | 输入卡片 160px 高但大部分空白，警告“角色聊天尚未分配模型…”以 11px 灰字塞在底部 | 输入框自适应高度（1–8 行，最小 56px）；“未分配模型”改为输入框上方的内联提示条（警告色左边条 + “去分配”按钮），能操作的问题必须给出操作入口 | 阻断性问题用灰色小字等于没提示 |
| 3.3.4 | Token 计数 `4,548 / 32,768 tokens` 用蓝色实心胶囊，像按钮 | 改为次要色等宽数字文字；超过 80% 变警告色，超过 100% 危险色；悬停显示上下文预算明细（复用 ChatContextPanel 数据） | 颜色应表达状态，而不是装饰 |
| 3.3.5 | 角色头像为通用线框图标，消息流缺少角色辨识 | 无头像时生成“首字母 + 由名字哈希得到的低饱和底色”头像；头像 32px，与名称基线对齐 | 多角色/群聊时快速辨认说话人 |

### 3.4 右栏面板（ChatContextPanel / ChatSessionPanel 等）

- “当前会话”卡片内标题、名称、状态、标签全部加粗，无层级 → 采用“标签（12px 次要色）/ 值（14px 主色）”两列表单布局；分组用小号大写眉标 + 间距，不用灰底卡片套卡片。
- 五个页签（上下文/角色/玩家人设/记忆/会话）文案长度差异大 → 改为图标 + 短标签的分段控件，或垂直图标条 + 展开面板（参考 VS Code 活动栏），也顺带解决 3.1.2。

工程落地：
- 3.1 缺陷修复与 P3（ChatView 拆分）无冲突，可直接做；3.2/3.3 必须在 P3 拆分完成后进行，避免在 55KB 的 `ChatView.xaml` 上做大面积改动。
- 消息 hover 操作栏用 `DataTemplate` 内 `Trigger IsMouseOver` + `IsKeyboardFocusWithin` 实现，保持 AutomationId 不变（测试仍能通过 UIA 找到隐藏但已加载的按钮，Opacity=0 不影响 UIA；**不能**用 `Visibility=Collapsed`）。
- 发送/停止同位切换：复用现有 Send/Stop 命令，仅改模板；两个按钮的 AutomationId 都保留。

## 9. 设计系统落地（跨页面的共同基础）

> 第 1–8 节中的大部分条目依赖这一层。先建 Token 和组件样式，再逐页替换，避免每页各自实现。
> 社区实践核对（2026-10-03 检索）：主流做法是“原始色值（Colors）→ 语义画刷（Semantic Brushes）→ 样式/模板只引用语义键”的两层结构，运行时一律 `DynamicResource`（参考 lepoco/wpfui 的 ApplicationThemeManager、MaterialDesignInXamlToolkit 的调色板机制）。本项目已具备语义画刷 + `DynamicResource` 的基础，**不引入 WPF UI / MDIX 等新依赖**，只补齐缺失的 Token 类别。

## 14. 文字边缘锯齿排查（2026-10-03，只读）

用户反馈：小号灰字、卡片内标题边缘锯齿明显（截图：跑团页“玩家席位”卡片）。

### 已确认的代码事实

| # | 事实（位置） | 影响 |
|---|---|---|
| 14.1 | `Light.xaml:70–99` 对 `Window`、`TextBlock` 等的隐式样式强制 `TextFormattingMode=Display` + `TextRenderingMode=ClearType` | **Display 模式 = GDI 兼容的整数像素排版 + 字形 hinting**。对拉丁字母小字号有利，但对中日文 12–14px 的笔画会被“吸附”到像素网格，横竖笔画变粗、斜笔画与转折发毛，观感就是“有锯齿” |
| 14.2 | `InterfaceSettingsRuntime.ApplyTextRendering()` 在缩放 ≠100% 时给**窗口根**设 `Ideal`，但 `TextBlock` 隐式样式（`Light.xaml:92–99`）仍显式设 `Display`，**样式 Setter 优先于继承值** | 缩放非 100% 时，窗口层想用 Ideal，实际每个 TextBlock 仍是 Display，再叠加 `LayoutTransform` 缩放 → 文字被放大后再吸附，锯齿更重。这是自相矛盾的设置，属于代码问题 |
| 14.3 | 卡片样式使用 `DropShadowEffect`（`CardShadowEffect`、`AppicaDashboardCardShadowEffect`、`AppicaPrimaryPanelShadowEffect` 等）| WPF 对带 `Effect` 的元素会整棵子树**离屏栅格化**，其中文字退化为灰阶抗锯齿（失去 ClearType 的子像素平滑），边缘更软、更“毛”。截图中文字所在的白色卡片正是此类 |
| 14.4 | 带 `AllowsTransparency="True"` 的弹出层（`Light.xaml:378/1327`、`ChatView.xaml:102/486`、`WorldbookView.xaml:58`）| 分层窗口同样不能用 ClearType，弹出菜单/下拉里的文字会是灰阶抗锯齿 |
| 14.5 | 无 `app.manifest`、`csproj` 无 DPI 配置；字体为 `Microsoft YaHei UI`（`Light.xaml:4`）| 依赖 WPF 默认 DPI 行为；微软雅黑 UI 小字号靠自带 hinting 点阵优化，在 Ideal 模式下也不会难看，但在 150% 等非整数缩放下需实测 |

### 不是代码问题的部分（需要用户侧确认）
- Windows 的 ClearType 开关与“平滑屏幕字体边缘”设置；
- 显示器缩放比例（125%/150% 时 Display 模式问题最明显）；
- 截图工具（`PrintWindow`）会把 ClearType 的彩边转成灰阶，**基线截图本身不能作为判断依据，请以屏幕肉眼观感为准**。

### 修复方案（按风险从低到高，均落在 `Light.xaml` / `InterfaceSettingsRuntime.cs`，待并行对话提交后执行）

1. **统一为 `Ideal` + `ClearType`，删掉样式里写死的 Display**（14.1 + 14.2）：
   - 删除 `Light.xaml` 中 Window / InterfaceScaleRootStyle / TextBlock 的两处 `TextFormattingMode=Display`，改由 `ApplyTextRendering()` 单一入口控制；
   - `ApplyTextRendering()` 默认也用 `Ideal`（保留 `TextRenderingMode=ClearType`）。
   - 同时检查 `AppicaShell.xaml:65/75/472`、`MainWindow.xaml:320`、`Light.xaml:1609` 的显式 Display。
   - 取舍：Ideal 在 100% 缩放下，部分拉丁小字可能比 Display 略软；中文通常更均匀。**建议加一个“文字渲染：清晰（Display）/ 平滑（Ideal）”设置项**，默认平滑，让用户按显示器选择（默认值变更需确认）。
2. **卡片阴影不包住文字**（14.3，同 12.2.7）：把阴影挪到卡片下方的独立兄弟 Border，或列表型卡片直接取消阴影改用描边；这样文字所在的元素不再带 `Effect`，恢复 ClearType。
3. **弹出层**（14.4）：`AllowsTransparency` 仅为圆角/阴影服务时，评估改为不透明矩形圆角 + `Popup` 默认渲染，或接受灰阶（影响面小，最后做）。
4. **整数缩放**：缩放档位限制为使 `字号 × 缩放` 接近整数像素的档位（如 100/125/150/200），避免 13.5px 这类半像素字号导致的模糊。需先确认当前缩放档位列表。
